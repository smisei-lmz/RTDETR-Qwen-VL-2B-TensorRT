# 共享实验室工位离席巡检

> 场景继续沿用；下文Day命令运行已有Python ROS/Transformers实现。新的C++/llama.cpp版本按 [6个大任务计划](每日开发路线.md) 的任务3–5实现与验收。


完整程序怎样运行、数据经过哪些模块，先看 [代码流程与数据流](代码流程与数据流.md)；本文用于准备素材、启动和验收场景。

本项目使用 RT-DETRv2-S 持续检测人员与常见物品。确认工位先有人使用、随后持续无人后，取一张独立快照给 Qwen2-VL，生成可回看的现场检查记录。无需机器人；电脑、工位视频即可完成 PC 阶段。

## 检测与大模型的分工

- RT-DETR：持续输出类别、框、分数，使用 COCO80 预训练权重，默认 `PekingU/rtdetr_v2_r18vd`。
- 状态机：根据同帧快照中的人员检测确定是否触发；默认先持续有人 2 秒，再持续无人 10 秒。
- VLM：描述这张快照中物品的外观、位置和需要人工交接确认的事项。它不承担无人计时，不认定物品所有权、遗失、设备是否通电或工位是否可分配。
- 记录：保存事件 ID、源会话/帧号/时间戳、JPEG、问题、模型回答和终态。

大模型只在事件或手动提问时运行。它使用自己的视觉编码器，不接收 DETR 中间特征。它的收益应通过报告准确性与人工复核效率评估，不能只以“能输出文字”作为验收。

## 先跑不需要模型的规则演示

在项目根目录执行：

```bash
python tools/workstation_demo.py
python -m unittest discover -s ros_ws/tests -v
```

`runs/workstation-rule-demo/timeline.json` 展示空桌、有人、短暂漏检、返回和离席。只能生成一条 `MOCK_RULE_ONLY` 事件。这是合成检测观察的状态机测试，没有运行 DETR、相机或 VLM，不能当作视觉效果演示。

## 准备真实工位素材

固定机位，对准单个工位的人员活动区域。录制 30fps、约 30 秒的视频：

1. 空桌 3 秒。
2. 人坐下至少 5 秒，放置背包、杯子或书本。
3. 人离开至少 15 秒，镜头保持不动。
4. 可再录人员返回，用于检查旧报告失效。

选择人员与物品清楚可见的一帧，保存为自己的 `reference.jpg`。在 `config.json` 中填写 `image` 为该图片路径、`video` 为视频路径。权重可填 Hugging Face 模型 ID 或本地模型目录；旧 `.pt`、`.engine` 和旧参考结果不能沿用。

## 电脑上的两条入口

### Python 功能入口：视频或可访问的相机

完成环境搭建、安装两份 requirements、构建 ROS workspace 并 source 后：

```bash
source /opt/ros/humble/setup.bash
source .venv/bin/activate
source ros_ws/install/setup.bash
ros2 launch edge_assistant workstation.launch.py source:=/absolute/path/workstation.mp4
```

用 `source:=0` 访问 OpenCV 能打开的相机；WSL 能否访问相机取决于设备转发与驱动，可先使用视频。此入口使用 Python/PyTorch RT-DETR，不能记为 C++ TensorRT 的性能。

可以先加 `vlm_backend:=mock` 检查事件、Action 和文件保存；输出明确为 MOCK。真实报告用默认 `qwen2_vl`。两个模型是否能在 8GB 显存下同时驻留必须实测。

### C++ / TensorRT 主线：沿用 37 天课程

```bash
python days/day03/run.py --image /absolute/path/reference.jpg
python days/day04/run.py --image /absolute/path/reference.jpg
python days/day05/run.py --image /absolute/path/reference.jpg
# 按日程完成 C++ / CUDA / TensorRT / ROS 的先修项
python days/day19/run.py --video /absolute/path/workstation.mp4 --frames 900
python days/day25/run.py
```

Day19 把视频解码成 `data/video/*.ppm`（或 inspection_source 指定目录）。已有 PPM 时会拒绝混写，重跑可追加 `--inspection-source data/workstation-run2`，Day25/30 也传入相同目录。源视频按30fps回放；源视频帧率应与当前 30fps 回放配置一致。该路径不保留原始 PTS，不是相机曝光时间测量。若录制文件不足 900 帧，以实际提取帧数为准；需保证回放中无人持续时间超过阈值。输入序列循环播放时，每次重新确认有人后可产生新的事件。

Day25/30 默认使用 `config.json` 中的 `inspection_source`（默认 `data/video`），不再对单张参考图片定时提问。Day36 在 Jetson 上使用同一场景；没有板卡时完成 PC 阶段即可，不能标记板端验收通过。

## 参数与状态边界

| 参数 | 默认 | 含义 |
|---|---:|---|
| `occupied_s` | 2 | 确认连续有人所需的源时间跨度 |
| `absent_s` | 10 | 确认离席所需的连续无人跨度 |
| `workstation_roi` | `0,0,1,1` | 人员活动区域，归一化 x1,y1,x2,y2；判断人员框中心是否落入区域 |
| `report_dir` | `runs/workstation` | 事件图片、JSON 和事件日志保存目录 |
| `auto_ask` | 场景模式为 false | 巡检禁止同时定时提问 |

例如：`ros2 launch edge_assistant workstation.launch.py source:=/path/video.mp4 absent_s:=5.0 workstation_roi:="0.1,0.1,0.9,1.0"`。

ROI 限制的是人员状态判断，不裁剪 VLM 快照。首版对准一个工位；没有跨摄像头追踪、人员身份识别或任意多工位管理。物品检测仅支持预训练类别，不应假设它能识别所有实验器材。

- 开机空桌不触发；短暂人员出现不算已占用；短暂漏检不算离席。
- 状态机使用源帧时间戳，不以接收次数或回调等待时间计时。无新帧不能证明无人。
- 快照间隔超过默认 3 秒会重置状态；旧帧/重复帧不推进计时，源会话重启需重新确认占用。
- 默认快照约 1Hz，触发时间存在采样粒度；网络丢包、遮挡、检测漏检仍需真实场景评估。
- 每次已确认的“有人→无人”只触发一次。再次连续有人才能重新布防。
- 事件绑定触发时的独立图片，不会因为排队而换成另一帧。事件输入过期会丢弃并记录。
- 人员返回或观察流失效时，取消待处理/运行中的巡检；取消确认前保持 single-flight。已保存报告是历史证据，并不实时代表当前工位。
- 模型忙时新事件记为 `SKIPPED_BUSY`，不会无限排队。首版没有失败自动重试；可以人工提问复核。

## 查看报告与人工追问

```bash
ros2 topic echo /assistant/answer
ros2 topic pub --once /assistant/question std_msgs/msg/String "{data: '请指出画面中的背包和杯子分别在哪里'}"
```

`runs/workstation/<event_id>.jpg` 是事件图片；同名 `.json` 是该事件的最新状态；`events.jsonl` 保留状态变化。报告用源帧时间戳而不是文字推断发生时间。成功状态为 `OK`，但 MOCK 后端的模型名和回答会明确标明无视觉理解。

手动问题针对最新快照，是独立问答，不会篡改已记录事件；要分析历史图片，可将该 JPEG 交给 `tools/ask_image.py`。

## 验收

录制至少包含：一直空桌、短暂遮挡、真实离席、人员返回、断流、模型忙六种情况。记录事件误触发/漏触发、触发延迟、报告事实错误、模型调用次数；保存 VLM 开关前后检测 P95/P99 和峰值显存。没有实测，不填写准确率或 FPS。
