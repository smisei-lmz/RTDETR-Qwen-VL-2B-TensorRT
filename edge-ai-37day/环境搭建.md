# 环境搭建与阶段依赖

> 本文件保留现有实现的环境与旧实验命令；Day编号属于旧版。新版按 [6个大任务](每日开发路线.md) 推进，llama.cpp版本与构建配置在任务3确认，DMA-BUF环境不作为主线前置。


所有学习命令默认在 **WSL Ubuntu 22.04 的终端**运行。前两天也可在 Windows Python 运行，但 CUDA/C++/ROS 主线统一在 Linux，避免混用路径、Python 包和编译器。

## 1. WSL 与目录

在 Windows 终端检查 `wsl --status` 和 `wsl -l -v`，确认 Ubuntu 22.04 使用 WSL2。WSL 内运行 `nvidia-smi`；GPU 应被识别。WSL 使用宿主 NVIDIA 驱动，不要在 WSL 安装 Linux 显示驱动来替代它。

将压缩包放到 Windows 下载目录后，在 WSL 解压到 `~/projects/edge-ai-37day` 或其他 Linux 目录。避免直接在 `/mnt/c/` 做大批小文件编译；解压后以包含 `days/` 的目录作为项目根目录。

```bash
sudo apt update
sudo apt install -y build-essential cmake ninja-build git unzip python3-venv python3-pip pkg-config libgl1 libglib2.0-0
python3 days/day01/run.py
python3 days/day02/run.py
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
python -m pip install --upgrade pip
```

Ubuntu 22.04 的系统 Python 3.10 与 ROS2 Humble 配套。`--system-site-packages` 让虚拟环境能看到 apt 安装的 ROS Python 库；避免换成 Python 3.12 后期待 apt 的 rclpy 直接可用。后续新终端都要激活同一 `.venv`。

## 2. Day03–06：真实模型

先根据宿主驱动和 [PyTorch 官方安装说明](https://pytorch.org/get-started/locally/) 安装匹配的 CUDA PyTorch 与 torchvision。当前探针的驱动为 572.83，不能因为安装器默认最新，就假设任意 CUDA 版本都受支持。

一个可作为 PC 起点的固定组合是 PyTorch 2.6.0 / torchvision 0.21.0 / cu126。以下命令是配置建议，本次未执行安装或验证这组 GPU 软件：

```bash
python -m pip install torch==2.6.0 torchvision==0.21.0 --index-url https://download.pytorch.org/whl/cu126
python -m pip install -r requirements-pc.txt
python -c "import torch; print(torch.__version__, torch.cuda.is_available()); print(torch.cuda.get_device_name(0))"
```

若官方已不提供对应 wheel，选择官方兼容组合并保存版本，不要强装不匹配的 torch/torchvision。Jetson 不用上面的 x86 PC 方案，见第 6 节。

安装与本机 CUDA/驱动匹配的 TensorRT Python 和 C++ SDK，参考 [TensorRT 安装指南](https://docs.nvidia.com/deeplearning/tensorrt/install-guide/index.html)。项目使用 TensorRT 8.6 及之后版本的 named-I/O / enqueueV3 接口；必须验证所选具体版本。先确认：

```bash
python -c "import tensorrt as trt; print(trt.__version__)"
```

**pip 中能 import tensorrt，不等于系统存在 C++ 的 NvInfer.h 和 nvinfer 链接库。** Python 与 C++ 推理库应来自一致版本，避免引擎在 Python 构建而 C++ 反序列化失败。安装 TensorRT tar SDK 时可在同一终端设置：

```bash
export TENSORRT_ROOT="$HOME/sdk/TensorRT-your-version"
export LD_LIBRARY_PATH="$TENSORRT_ROOT/lib:${LD_LIBRARY_PATH:-}"
```

将示例路径替换为实际安装路径。CMake 从 `$TENSORRT_ROOT/include` 和 `lib` 查找。某些 wheel 发行形式会另带库路径，按所选发行版文档配置，不能靠随意复制 `.so` 解决版本冲突。

Day03/04/05 首次加载会下载 PekingU/rtdetr_v2_r18vd；也可在 config.json 的 weights 指定本地 Hugging Face 模型目录。准备自己的真实工位照片（--image）和显式 COCO 数据清单（--dataset data/coco_eval.json），数据不会自动下载。安装 requirements-pc.txt 中固定的 Transformers 版本；详见 [RT-DETR部署说明](RT-DETR部署说明.md)。模型与数据集许可按发布方条款使用。

## 3. Day07–19：C++、CUDA 与 TensorRT

CPU C++ 只需要 CMake/C++17：

```bash
python days/day07/run.py
```

Day12 前安装匹配的 **CUDA Toolkit**，包含 `nvcc` 和开发头文件。PyTorch wheel 的 CUDA runtime 不包含完整开发工具链。WSL 安装方式参考 [CUDA on WSL 指南](https://docs.nvidia.com/cuda/wsl-user-guide/index.html)，优先安装 Toolkit 包，避免拉入 Linux 显示驱动。

```bash
nvcc --version
cmake --version
cp config.example.json config.json
```

`config.json` 的 `cuda_arch=89` 针对已探测的 RTX 4060 Laptop；换 GPU 要改成对应 SM。Jetson Orin 使用 `jetson_cuda_arch=87`。这些是编译目标，不是 CUDA 版本号。

Day12 构建 CUDA；Day15 才打开 TensorRT C++。若 Day15 提示缺 NvInfer.h，请补全 SDK，不要把失败切换成 CPU 后写“通过”。Nsight Systems 为 Day18 的可选依赖；默认不要求它，安装后用 `--profile`。

## 4. Day20–23、26：ROS2 Humble

按 [ROS2 Humble Ubuntu deb 官方说明](https://docs.ros.org/en/humble/Installation/Ubuntu-Install-Debs.html) 配置语言环境、软件源与密钥，再安装：

```bash
sudo apt update
sudo apt install -y ros-humble-ros-base ros-dev-tools python3-colcon-common-extensions python3-rosdep ros-humble-sensor-msgs ros-humble-action-msgs
source /opt/ros/humble/setup.bash
source .venv/bin/activate
python -m pip install 'empy==3.3.4' catkin_pkg lark
python -c "import rclpy; import colcon_core; print('ROS Python ready')"
python days/day20/run.py
```

如 `rosdep` 尚未初始化，按官方教程初始化并更新；使用 `rosdep install --from-paths ros_ws/src --ignore-src -r -y` 安装声明依赖。课程入口会 source ROS 和 workspace，并使用当前 Python 调用 colcon，减少虚拟环境与系统 Python 混用。若以前用不同 Python 构建过，请先将旧的 `ros_ws/build`、`install`、`log` 移到备份目录，再用同一个 Python 重建。

检查 ROS 基础命令：

```bash
source ros_ws/install/setup.bash
ros2 node list
ros2 topic list
ros2 interface show edge_interfaces/action/AnalyzeScene
```

课程的 live 观察/Action 测试最好在单独终端设置相同的 `ROS_DOMAIN_ID`，例如 `export ROS_DOMAIN_ID=37`，防止其他 ROS 项目干扰。WSL 内多节点先完成，再考虑跨机器 DDS 网络。当前桥接只支持默认系统时间，不支持 `/clock` 仿真时间。

## 5. Day24–30：真实 VLM

保留前面匹配的 GPU PyTorch，再安装：

```bash
python -m pip install -r requirements-vlm.txt
python days/day24/run.py
```

默认下载 `Qwen/Qwen2-VL-2B-Instruct`；可以通过 `--vlm-model /path/to/local-model` 使用本地目录。实现固定 transformers 4.49.0，采用 FP16、SDPA、有限图像 token 和输出 token；没有自动安装 FlashAttention 或量化依赖。

8GB 显存应先做单图验证，再做 Day25 并发。若 OOM，记录峰值和配置，先减少视觉 token、输入图尺寸、输出 token、并发 lane；任何改动都重新检查延迟与答案质量。默认仅一个 VLM 请求；协作取消不能立即抢占已提交的 GPU kernel。

若环境可用，保存：

```bash
python -m pip freeze > runs/python-freeze.txt
nvidia-smi > runs/gpu-environment.txt
```

记录是你真正运行的版本，仓库中的依赖范围只是起点，并非在所有新版本上验证过的锁文件。

## 6. 买板后的环境

以 Jetson Orin Nano + JetPack 6 / L4T R36 为迁移目标。使用该板与相机厂家支持的具体版本，记录 `/etc/nv_tegra_release`。安装 JetPack 对应的 CUDA/TensorRT 开发组件、`v4l-utils`、多媒体 API 头文件和 ROS Humble。相机必须已有可用驱动；本工程不会自动生成驱动。

板端 PyTorch/torchvision 应采用 NVIDIA 或所选 JetPack 明确支持的 aarch64 构建，参考 [PyTorch for Jetson](https://docs.nvidia.com/deeplearning/frameworks/install-pytorch-jetson-platform/index.html)。不要照抄 PC 的 cu126 wheel 命令。若选容器，要确认设备、EGL、CUDA、共享内存与 ROS 网络均已配置；本工程不隐藏容器部署成本。

板端 TensorRT 必须重新构建 engine，课程保存在 `artifacts/jetson-models/`。**不要把 PC raw plan 直接复制当成可移植模型。** 可以共享 ONNX/权重，但推理引擎与 GPU/TRT 组合有关。

共享路径需要 `nvbufsurface.h`，CMake 默认从 `/usr/src/jetson_multimedia_api/include` 查找，库目录检查 `nvidia`/`tegra`。如果 SDK 安装位置不同，用 CMake cache 参数显式设置 `NVBUF_INCLUDE`/`NVBUF_LIB`。

相机相关配置在 `config.json`：设备、尺寸、YUYV/NV12、BT.601/709、full_range。用 `v4l2-ctl --all --list-formats-ext` 查驱动实际协商结果。仅有 MJPEG、多平面接口、DMABUF import 不支持或 stride 不兼容时，本共享路径会失败，需要采购兼容设备或实现明确适配，不能把 fd 强转成 CUDA 指针。

## 常见阻塞点

| 现象 | 应检查 |
|---|---|
| WSL 看不到 GPU | WSL2、宿主驱动、重启状态；先解决 nvidia-smi |
| torch CUDA 可用但 nvcc 不存在 | 单独安装 Toolkit 开发环境 |
| Python TRT 可用，C++ 找不到头文件 | C++ SDK 与 CMake 路径 |
| engine deserialize 失败 | raw plan 包装、GPU/TRT 版本一致性 |
| C++ 框和参考不一致 | RGB/BGR、双线性拉伸、/255、归一化坐标、top-k 输出契约 |
| rclpy 导入失败 | Python3.10、ROS source、venv system-site-packages |
| 同时跑 VLM 和检测 OOM | 两者实际峰值、token/图像大小、lane 数、其他进程占用 |
| Jetson EGL 初始化失败 | NVIDIA EGL 运行环境及无显示器配置；按具体 JetPack 文档处理 |
| DMABUF QBUF 或布局校验失败 | 驱动 import 能力、格式、stride、offset、分配器兼容性 |

失败日志就是适配依据。先跑通拷贝基线，再验证共享链路，每个阶段分别记录。
